## 二、輸出欄位契約

| 欄位名稱 | 型別／限制 | 用途 | 畫面標籤 | 如何查原文 |
|---|---|---|---|---|
| title | string | 產生筆記標題 | 筆記標題 | 確認標題符合課程內容 |
| summary | string | 整理課堂摘要 | 內容摘要 | 對照原始筆記確認沒有新增事實 |
| key_points | array[string] | 條列重要觀念 | 重點整理 | 逐項比對原文 |
| keywords | array[string] | 擷取重要關鍵字 | 關鍵字 | 確認關鍵字有原文依據 |
| review_questions | array[string] | 產生複習問題 | 複習問題 | 確認問題依據原始內容 |
| missing_information | array[string] | 提醒資訊不足 | 需要補充的資訊 | 確認缺少資訊沒有被自行補完 |

本專題使用 JSON Schema 定義六個必要欄位，並設定 additionalProperties 為 False，避免模型輸出未定義的欄位。

### 6. 最有用的欄位

我認為最有用的是 **key_points（重點整理）** 與 **missing_information（需要補充的資訊）**。

key_points 可以協助學生快速掌握上課重點，減少重新閱讀整份筆記的時間。

missing_information 則能提醒學生哪些內容沒有記錄完整，避免在複習時誤以為筆記已經包含全部資訊。

### 7. 已知限制與未來改進

目前系統只能根據使用者輸入的文字進行整理，無法確認老師實際授課內容是否完全正確。

即使使用 JSON Schema，也只能限制輸出格式，不能保證所有整理內容都完全正確，因此仍需要人工核對。

未來希望增加筆記分類、歷史紀錄保存、檔案上傳及更多複習功能，讓系統成為更完整的學習輔助工具。

### 8. 專題心得

這次專題讓我了解如何將生成式 AI 與 Streamlit 結合，製作具有實際用途的網頁應用程式。

除了學習 API 呼叫與 JSON Schema 結構化輸出，也了解到輸入驗證、錯誤處理和雲端部署的重要性。

透過這次實作，我認為 AI 不只是產生文字的工具，也可以協助學生整理資訊、提高學習效率。不過 AI 產生的內容仍然需要使用者自行確認，才能避免錯誤資訊影響學習成果。
